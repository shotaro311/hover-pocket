# HoverPocket Windows安定化 要件定義

更新日: 2026-09-28
状態: 完了ラインAと基本機能の総点検をユーザーが選択。具体的な確認項目は、その範囲を満たす実装方針として整理。
この文書の確定は、検証や修正が完了したことを意味しない。

## 0. 概要

HoverPocket Windows版の開発基準と基本動作を整え、独自ファイルライブラリの開発に進める安定した土台を作る。

## 1. 目的

公開版、開発ブランチ、ローカルの未コミット変更を整理し、採用するコードと残課題を明確にする。既存データを維持して日常利用できる状態を確認する。

## 2. 想定ユーザー

まず既存Windows利用環境での安定動作を確認する。今回、一般向け正式配布の完成までは求めない。
ユーザーは最近Windows版を使っていないため、特定症状を前提にせず基本機能を一通り確認する。

## 3. 主要な対象

- 開発基準の整理: Mac公開版、Windows公開版、main、関連する未統合変更を比較し、Windows安定化の基準を選ぶ。未コミット変更を保全し、既に解決された変更を重ねない。
- 常駐と画面操作: 起動、終了、二重起動の扱い、ホバーによる表示、開閉、設定保存、スリープ復帰を確認する。
- 既存機能の安定性: クリップボード画像の保存・再コピー・ドラッグ、タイマー等の通知を重点確認し、Calendar、Controls、付箋、電卓も既存動作を壊さない。
- 更新とデータ保持: アプリの更新・再起動によって設定、履歴、お気に入り、付箋や既存の接続情報が意図せず失われないようにする。

## 4. 入口の技術仕様

- 既存のWindowsデスクトップアプリ構成（C# / WPF / WebView2）を継続する。全面的な作り直しは行わない。
- 既存の保存形式と更新経路を優先する。データ形式変更が必要なら移行と復旧方法を別途定義する。
- Mac版の既存配布経路を維持し、Windowsの変更と配布を区別する。

## 5. 開発方針

速度より安定性と既存データの保全を優先する。機能追加を広げず、ライブラリ開発の土台に必要な範囲で完了させる。

## 6. 今回の対象外（選択Aに基づく）

- 新しいファイルライブラリ、iPhone連携、ファイル同期の実装。
- 開発途中のAI音声・自作アプリ生成機能を完成させること。
- Macとの全機能一致、UIの全面改修。
- 一般向け正式版の公開、コード署名証明書の取得。

既存の有効な機能を削除するという意味ではなく、今回の完成条件に含めない。

## 7. 完了条件

1. 採用するソースの基準、ローカル変更の扱い、今回持ち越す課題が明確になっている。
2. 同じ対象コードからビルドでき、変更に関係する既存検証が成功する。
3. Windows実機で起動・ホバー・開閉・画像保存とドラッグ・通知・スリープ復帰を確認する。
4. アプリの再起動、更新とデータ保持を確認する。実更新が未確認なら、その項目を完了扱いにしない。
5. 通常操作を妨げる既知のクラッシュや保存失敗が解消され、残る制約が説明できる。
6. ライブラリ機能を追加するために、AI音声などの未完成機能の有効化を前提にしない。

### 基本機能の確認範囲

| 分野 | 確認する動作 |
| --- | --- |
| 起動・常駐 | 通常起動、終了、再起動、二重起動、設定に従った自動起動、トレイ操作 |
| ホバーパネル | 開閉、機能切替、サイズ変更、文字入力、他アプリの操作への影響 |
| 画面・復帰 | 現在接続されているモニターと表示倍率、スリープ・ロック解除後の復帰 |
| クリップボード | テキスト・画像の取得、再コピー、お気に入り、画像ドラッグ、履歴保存 |
| 付箋 | 作成・編集・保存・並べ替え・アーカイブ、再起動後の保持 |
| タイマー | 作成・開始・停止・満了通知、パネルを閉じた状態での動作 |
| 電卓 | 四則演算、キー入力、履歴の基本操作 |
| Calendar | 接続状態の表示、既存予定の読み取り、通信失敗時の表示。更新操作は合成データで確認し、実予定を無断作成・変更しない |
| Controls | 音量・輝度・メディアの表示と操作、機器が非対応の場合の案内 |
| 更新・保存 | 更新検出、適用・再起動、設定・履歴・お気に入り・付箋・接続情報の保持 |

実機操作にはテスト用データを使い、既存データの削除や初期化で検証しない。音量等を試験で変更した場合は元の値へ戻す。PC全体のスリープ・再起動は他の作業に影響するため、実施時点で調整する。各項目を成功・失敗・未検証・対象外として記録し、機器や認証に依存する未検証を成功として扱わない。

## 8. 調査時点の事実

2026-09-27の読み取り調査では、Windows公開版は0.2.8、当該PCのインストール済み版は0.2.7、既存開発フォルダは48697d1に未コミット変更がある状態だった。Mac公開版、Windows公開版、mainの履歴は分岐していた。実装開始時に再確認する。

## 9. 実装開始時に確定する事項

- 現在のPCのOS・モニター・表示倍率・インストール版を読み取り確認し、実機検証の基準とする。
- 最新ソースと既存の未コミット変更の比較に基づいて作業基準を選ぶ。
- 実更新の候補版と復旧方法を具体化する。今回の範囲に新たな一般公開は含まない。
- ライブラリ開発へ進めるかを、上記完了条件と未検証項目から判定する。
