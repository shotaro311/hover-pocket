# 素材ライブラリ初期版の要件

## 1. 目的・正本・決定の扱い

Eagleを介さず、上端のポケットでファイルを保存・検索・取り出し、整理用ウィンドウで分類できる。基本機能は端末内で完結し、配布アプリをインストールした一般ユーザーが使える。

ユーザーが明示した条件は、独立した素材ライブラリ、誰でも利用できる配布アプリ、Eagleを参考にした軽快な操作、**動画・PDFのプレビューも初期版に含めること**、**プレビューでは上端につながったパネル自体が素材に合わせて自動拡大し、その中で動画/PDFを操作でき、全画面へも切り替えられること**。その他の細部は以下の実装前提として定める。初期版は本番品質で実装し、保存と復元の検証が完了してから配布する。

この文書が機能範囲・動作・受入条件の正本。[設計資料](../plan/20261002_ASSET_LIBRARY_DESIGN.md)は理由と構成を説明し、範囲が異なる場合は本書を優先する。既存のAI用機能台帳とクリップボード履歴の契約は維持する。以下の要件は未実装で、性能値は測定結果ではない。

## 2. 初期版の範囲

| 区分 | 初期版で満たすこと |
| --- | --- |
| 保存対象 | 任意形式の通常ファイル。ドラッグ、ファイル選択、フォルダ選択、明示的なクリップボード画像保存 |
| 共通必須プレビュー | JPEG・PNGの画像、MP4のH.264動画（音声はAACまたは音声なし）、暗号化されていない通常のPDF |
| その他の形式 | 原本保存、名前・種類・サイズの表示、分類、検索、外への取り出し。「アプリ内プレビュー未対応」と表示。拡張子だけで対応を断定しない |
| 整理 | 名前検索、タグ、分類フォルダ、お気に入り、最近、未分類、条件を保存するスマートフォルダ、一括操作、ゴミ箱と復元 |
| 持ち出し・バックアップ | 原本と公開されたメタデータのエクスポート、既定場所の空ライブラリへの復元 |
| OS | WindowsとmacOSの同じ動作契約。実装・受入・配信はOSごとに行える |
| 後続段階 | 端末間同期、iPhone共有、Eagleからの移行、OCR・画像の意味検索、編集・変換、類似重複検出、動画・PDF内の全文検索 |

H.265/HEVC・特殊な音声トラック・DRM・暗号化PDFのアプリ内表示は初期版の必須条件に含めない。追加コーデックの購入や外部アプリのインストールを必須にしない。既存HoverPocketの対応OS範囲を狭めず、メディア機能が不足する環境では保存・整理を利用でき、プレビューが使えない理由を表示する。

最初はユーザーごとに一つの管理ライブラリとする。Windowsは`%LOCALAPPDATA%\HoverPocket\AssetLibrary`、macOSは`~/Library/Application Support/HoverPocket/AssetLibrary`へ保存する。Windowsの既存設定・短期履歴のRoaming領域は変更しない。アプリのインストール・更新領域には保存しない。更新・明示ロールバック・アンインストール・再インストール後も原本とDBを保持することを受入対象に含める。場所の変更、複数ライブラリ、ネットワークドライブでの共同利用は後続段階。容量不足時は原因と空き容量を示し、保存済み原本を自動で消さない。

## 3. 保存と復旧

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-01 | アカウント・APIキー・Eagle・専用GPU・開発者のサーバーを要求しない | 未設定の新しいユーザー領域で、ネットワークを切って保存から取り出しまで行える |
| AL-02 | ファイル原本を元のバイト列のままコピーし、管理原本を読み取り専用で保管する。取り込み元を変更しない | 取り込み前後・再起動後・エクスポート後のSHA-256が一致。取り込み元が不変。クリップボードの画素データはAL-28の生成PNGを原本とする |
| AL-03 | 任意形式の通常ファイルを保存し、フォルダは再帰的に取り込む | 対応・未対応形式を混在させて保存できる。シンボリックリンク、ジャンクション、特殊ファイルを追跡せず、スキップした件数と理由を示す |
| AL-04 | コピー中は「保存中」、原本とDB登録の確定後は「保存済み」と表示する | 原本確定前・DB登録前・登録直後に強制終了しても、次回起動で完了を再認識または失敗として再試行できる。欠損を保存済みと表示しない |
| AL-05 | コピー中の変更・切断・容量不足・権限不足を項目単位で扱う | コピー前後で取り込み元のサイズ・更新情報を検査し、変化した項目は確定しない。他の項目を継続し、再試行できる。取消は未確定分だけを止める |
| AL-06 | 同じSHA-256の内容に対する素材と原本は、通常・ゴミ箱を通して最大一つにする。同名別内容は別素材にする | 同時取り込みでも一つに確定。通常素材には分類を追加し既存分類を維持。ゴミ箱素材は新規作成せず結果一覧に「ゴミ箱にあります」と復元操作を表示し、バッチを止めない |
| AL-07 | プレビュー生成の成功と原本保存の成功を分ける | 壊れた画像・動画・PDFも原本保存の結果を表示し、プレビュー失敗で原本を消さない。失敗した処理だけを再試行できる |

一時ファイルは原本と同じファイルシステムへ置き、書き込みを確定してから原本化・DB登録する。未完了記録から次回起動で復旧する。管理領域内のDBに登録されていない原本を自動削除せず、「未登録の原本」の件数と再取り込みを案内する。再開に取り込み元が必要なら明示する。欠損・サイズや更新日時の変化を利用前に検査し、「原本が変更されています」を表示して自動修復・削除をしない。バックアップでは内容ハッシュも検証する。

オンライン専用のOneDrive/iCloudファイルは取得中の状態を表示し、オフラインや取得失敗は項目単位で再試行する。読み取りを安全に確定できない書き込み中のファイル、macOSのパッケージ、フォルダ内の`.DS_Store`・`Thumbs.db`・`desktop.ini`はスキップ理由を示す。大量取り込みの開始前には件数・合計容量を表示し、1,000件以上または1GiB以上では一度だけ確認する。空き容量はコピー中も検査し、予備512MiBを割る前に未確定項目を停止する。大きいフォルダは走査を段階的に行い、全項目をメモリに保持しない。管理者権限の異なるアプリからのドラッグ等、OSが渡さない場合はファイル選択を案内する。

フォルダ取り込みは元の階層を分類フォルダへ再現する実装前提とする。選択したルートの名前で分類を作り、同じ親に同名分類があればその分類を再利用し、相対階層を所属として追加する。空フォルダも分類として残す。同じ内容の素材が複数階層にあれば原本を増やさず所属を増やす。外部フォルダの変更を後から自動同期しない。この選択はユーザー確認へ提示した推奨案を前提にしたもので、直接の回答とは区別する。

## 4. ポケットと整理画面

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-08 | 新しいProvider「素材」として登録し、ドラッグ時だけ一時表示する。ドラッグ中は自動閉鎖を抑える | 入口非表示・上端への直接移動・ドロップ・取消に対応。一時表示は前回選択の保存値を変えない。取消は元のProviderへ戻し、ドロップ成功時は結果を表示して通常閉鎖時に元へ戻す。「素材」非表示時はこのドラッグ入口を無効化 |
| AL-09 | 通常は最近の素材、お気に入り、検索と整理画面への入口を表示する | 保存中の進捗が見え、タグを付けなくても保存できる。整理画面を開く際は検索条件と選択を引き継ぐ |
| AL-10 | ホバーだけで他アプリの入力フォーカスを奪わない | 検索欄のクリックまたはキーボードでの明示操作で入力可能になる。フォーカス中は勝手に閉じない。入力完了・Escで通常状態へ戻る |
| AL-11 | アプリ外へ原本の独立したコピーをドラッグ・ファイルとしてコピー・選択先へ書き出せる | 両OSのファイル管理画面と少なくとも一つの別アプリで受け取れる。管理原本のパスやWebView専用URLを渡さず、移動を許可しない。外部アプリが編集しても管理原本のハッシュが不変 |
| AL-12 | 整理画面は左に分類、中央に一覧、右に選択中の詳細を置く | 左右を折りたためる。1280×720相当の作業領域で必須操作を使え、OSの表示倍率・大きな文字・Reduce Motionへ対応する |
| AL-13 | 選択・スクロール位置を、更新・プレビューの開閉で保持する | 項目追加で表示が飛ばない。絞り込みで選択素材が対象外になった場合は選択を解除して理由を示す。対象外の素材を詳細に残さない |
| AL-14 | マウスとキーボードで同じ主要操作ができる | 矢印で移動、Spaceでプレビュー、Escで戻る、Ctrl/Cmd+Fで検索、Ctrl/Cmdで個別選択、Shiftで表示順の範囲選択、余白からのドラッグで矩形選択。Shiftの範囲は未描画の項目も含め、絞り込み条件に従う。入力欄・日本語変換中には奪わない。トレイまたはメニューバーから整理画面を開ける |

「素材」は既存Providerの並び順・表示設定・通常選択の保存契約に従う。通常ホバーに追加の待ち時間を入れない。ドラッグでの一時表示には複数画面をまたぐ誤発動を抑える滞在判定を使い、値は実装検証で固定する。非表示の場合も整理画面はトレイ/メニューバーから明示的に開ける。

外へのファイルコピーはOSが受け取る独立したファイル参照とし、クリップボード画像のコピーとは別操作にする。「OSのアプリで開く」も独立したコピーを使う。外部へ渡したコピーは管理原本と区別した領域に置き、参照中に自動削除しない。残ったコピーの容量と明示的な整理操作を用意する。書き出し先の同名ファイルは確認なく上書きしない。通常検索中に別のアプリへフォーカスが移ると通常ホバーへ戻り、検索語を保持する。ポケットのプレビューはホバー離脱または別アプリへのフォーカス移動で閉じ、動画を停止して一覧へ戻る。全画面中も他アプリへの切替を妨げない。編集・保存のダイアログとファイルのドラッグ中はパネルを保持する。整理ウィンドウはホバー離脱で閉じない。

大容量のドラッグではファイル準備を非同期にし、マウスを離して待てることを表示する。準備が終わる前に離した場合は、同じ選択をもう一度ドラッグして引き渡す。引渡し済みの作業コピーは再利用しない。未引渡しの準備済みコピーも、分類/名前の変更、原本のサイズ/時刻の変更、コピーのサイズ/時刻の変更があれば無効とする。1GiB以上の素材で準備時間と、準備後のドラッグ開始時間を分けて計測し、実OS間の受入を行う。

初期版は音声・AIテキスト・生成ツール・MCPへ素材操作を公開しない。素材データを既存のAI機能台帳へ自動登録しない。

### パネル自体の自動拡大と全画面

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-31 | ポケットで素材をプレビューすると、上端につながったパネル自体を素材の表示縦横比に合わせて拡大する | 縦長・横長画像、EXIF回転、縦横動画、縦横PDFを検証。縦横比を保ち、再生/PDF操作部を残す。別の固定窓を開くだけで代替しない |
| AL-32 | 全画面へ切り替え、元の上端プレビューへ戻れる | ボタンとWindows F11/macOS Ctrl+Cmd+Fで切り替え。Escは全画面を解除し、通常プレビューでは一覧へ戻る。選択・再生時間・音量・PDFページ・ズームを保持。別モニターへは勝手に移らない |
| AL-33 | ポケットのプレビューはホバー離脱でパネルを閉じ、自動で一覧へ戻る | 背景アプリの入力をホバーで奪わず、別アプリで入力するとプレビューを終了する。閉じた後は次のホバーで一覧を開く。動画のソースと全画面状態を片付け、通常パネルの設定サイズを書き換えない。編集・保存ダイアログとドラッグ中は保持する。整理ウィンドウは対象外 |

2026-10-04のユーザー指定で、AL-33は固定表示からホバー離脱で閉じる動作へ変更した。今回の実装対象はWindowsであり、macOS側の対応は未実施。

通常プレビューのサイズは現在の画面の作業領域を基準に、幅90%・高さ85%を上限にして計算する。通常パネルの設定サイズを下限の希望値とし、それが上限を超える小さい画面では画面内に収める。上端の起点と同じ画面に置き、中央の接続を保持する。画像はEXIFを反映した表示寸法、動画は回転と表示縦横比、PDFは選択中ページの寸法から計算する。小さい画像を自動で過剰に拡大せず、空白と操作領域を許容する。

上限はHeader・ProviderHost・音声欄を含むパネル全体に適用する。Headerの高さと通常時の音声欄のモードを変えず、ProviderHostに残りの領域を割り当てる。素材の全画面では音声欄を表示せず、セッション自体は維持する。R-SHELL-006の全画面禁止は音声欄自身の表示モードに限り、素材プレビューには適用しない。

キャッシュを先に描画し、サイズ確定・原寸表示を待たせない。素材切替とPDFの縦横ページ変更でサイズを再計算し、古い要求の結果を適用しない。途中反転と連続操作を検証し、Reduce Motionでは即時切替にする。全画面中は画面の大きさを保ち、素材切替で窓サイズを揺らさない。再生・ページ送り・ズームはポケットの拡大パネル内と整理画面の双方で使える。

全画面は選択中の一画面だけに適用し、OS標準の全画面動作を優先する。全画面への遷移でプレーヤーを重複作成せず、再生中/一時停止の状態を保ち、再生を先頭から始め直さない。表示倍率・ノッチ・タスクバー/メニューバー・複数画面・画面切断を検証する。画面が切断された場合は利用可能な画面へ収め、通常設定を変えない。ほかのProviderへの明示的な切替ではプレビューを終了し、再生も止める。プレビュー終了後に通常サイズへ戻る際も、一覧の選択とスクロール位置を保持する。

固定/全画面プレビュー中のタイマー終了ではProviderを自動で切り替えず、入口の強調と通知だけを行い、プレビューと再生を維持する。通常時のTimerへの自動切替は保持する。窓の状態検査と画面再同期では素材の拡大/全画面を正常な状態として扱い、通常サイズへ戻さない。窓の再生成が必要な故障については、再生・ページ・ズームの引継ぎを別の受入で確認する。

Spaceは一覧からのプレビュー開始、動画プレビュー中の再生/停止、画像/PDFプレビュー中の終了とする。入力欄と日本語変換中は入力を優先する。複数画面でプレビューを開始した場合は後から開始した画面を残し、先の動画を停止する。

Escは日本語変換の取消、開いている操作ダイアログの終了、全画面の解除、プレビューの終了、検索入力の終了の順に処理する。ボタンにも「全画面を終了」「プレビューを終了」を明示する。変換中の入力を全画面/プレビューの閉鎖として扱わない。

工程3の冒頭で、既存の非アクティブ常駐窓からプレビュー固定・自動拡大・一画面の全画面・通常状態への復帰が可能か、各OSで小さい統合検証を行う。この工程ゲートを通過するまでプレビューUIの完成扱いにしない。

PDF内のスクリプト・添付の実行・外部リンクの自動遷移は行わない。暗号化PDFは保存・書き出しできるが、初期版ではアプリ内のパスワード解除を必須にしない。動画の対応可否はコンテナと映像・音声の組み合わせで判断し、拡張子がMP4でも必ず再生可能とは表示しない。

画像・PDFの描画ピクセル数とズームの上限は工程3の統合検証で固定する。OS標準のデコーダーでも全寸法の展開が起きないことを計測し、予算を保証できない素材は縮小表示または非対応の案内とする。

WindowsではPDFレンダラーと、ネイティブのメディア再生/埋め込みWebViewの動画を比較する。macOSはPDFKitとAVKit/AVFoundationを候補とする。工程3の前に、1080p/4Kの再生・シーク、閉鎖/切替後100ms以内の音の停止、プレーヤー参照の解放、Windows N等の不足機能の案内を小さい検証で確認してから採用する。OS内部メモリが解放されるまでの時間も別計測する。

WebViewへは選択中の素材IDに対して読み取りだけを許可し、切替後のアクセスを無効化する。動画の部分読み込みを検証する。ライブラリ全体の物理パスを公開しない。HTML/SVGなどを原本のままWebView文書として開かず、ドロップでページ遷移させない。別ライブラリが必要なら配布ライセンス・容量・各OS対応を確認する。現時点で統合済みとは扱わない。

## 6. 分類と検索

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-20 | タグと分類フォルダは複数所属・複数選択への一括適用に対応する | 所属を増やしても原本は一つ。フォルダ階層は循環を拒否。分類の削除は所属だけを外し、素材を削除しない |
| AL-21 | 名前・タグ名・拡張子の部分一致検索とタグ・分類・種類・取り込み日の絞り込みを組み合わせる | NFKC正規化とUnicodeの大文字小文字統一を同じ規則で適用。全角/半角英数字・カナを同一視し、ひらがな/カタカナは区別。1〜2文字の日本語も検索可能。異なる条件はAND、同じ分類内の複数指定はOR。条件と解除を表示 |
| AL-22 | 最近・お気に入り・未分類・スマートフォルダは同じ素材を参照する | 最近は取り込み日時の降順、同時刻はID順。未分類は分類フォルダへの所属なし。スマートフォルダは検索条件を保存し、新しい素材にも適用される。日付条件は端末のタイムゾーンで評価 |
| AL-23 | 一括分類とゴミ箱操作には「元に戻す」を提供する | 直前の一括操作を一単位として戻せる。初期版のUndoは同じ起動セッション内の直前操作を対象とし、再起動後はゴミ箱から復元できる |

名前の変更は表示名だけを変え、原本内容・ID・元の拡張子を維持する。Windowsの一覧ではファイル名のダブルクリックでその1件の名前を変更し、サムネイルのダブルクリックでプレビューを開く。名前の編集開始時は拡張子を除いて選択し、Enterで保存、Escで取り消す。タグ名と同じ親のフォルダ名は正規化後の重複を認めず、表示用の名前は保持する。分類フォルダの初期並び順は名前順。保存済み検索の種類条件は画像/動画/PDF/その他。テキスト検索は空白で分けた各語のAND、各語の名前・タグ名・拡張子の候補はOR。タグ・分類の複数条件は条件内OR、条件間AND。ユーザー入力をSQL/全文検索の構文として直接扱わない。

日本語変換中は検索しない。Enterまたは変換確定で即実行し、それ以外の入力は150msの無入力後に実行する。遅延前の入力から表示までの時間も参考値に含める。1〜2文字はtrigram索引だけに依存せず別の経路を実装・計測する。表示名・検索用正規化文字列・索引を実装時の共通fixtureで検証する。ファイル本文や動画音声は検索対象外。フォルダは整理用の所属で、OS上の原本ディレクトリとは別である。

## 7. ゴミ箱とバックアップ

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-24 | 素材はライブラリ内の復元可能なゴミ箱へ移し、通常検索から除外する | 原本・分類・タグを保持して再起動後も復元可能。同じ内容の再取り込みはAL-06の復元案内に従い、通常素材を新規作成しない。自動で永久削除しない |
| AL-25 | エクスポートは対象時点の原本と版番号付きメタデータを一組で出力する | 通常素材・ゴミ箱・分類・お気に入り・保存検索を含む完全バックアップができる。処理中の変更はその後の版へ含め、半端な出力を完了扱いにしない。原本欠損を成功扱いにしない |
| AL-26 | 復元前に形式・版・件数・ハッシュ・参照を検証し、既定場所の空ライブラリへ復元する | 両OS共通の正本fixtureを復元し、出力が同じ意味になることを各OSで検証。未知の版・壊れたハッシュ・領域外参照を拒否。現在の原本とDBを破壊しない |
| AL-27 | DBの版と更新を管理し、更新失敗から復元できる | migration・バックアップ・代表fixture・互換性検証を同時に用意する。未知の新しい版は書き込まず案内。キャッシュだけを消しても原本と分類が復元される |

復元はライブラリ全体を対象とし、既存素材との合成インポートは後続段階。既存素材がある場合は「現在のライブラリを退避」で同じ親領域の日時付きディレクトリへDBと原本を移し、既定場所に空のライブラリを用意する。退避は明示操作で、削除しない。必要容量を検査し、復元が成功するまで元の領域へ戻せる。別ドライブや複数ライブラリを選ぶ仕組みは追加しない。復元中の書き込みを停止し、失敗時の途中出力は利用中にしない。

エクスポートは版番号付き`manifest.json`と`originals/<素材ID>.<元の拡張子>`から成る通常ディレクトリを出力し、完了まで一時名称にする。通常素材、ゴミ箱、タグ、フォルダ所属、お気に入り、保存検索と由来フラグを含める。個人の元の絶対パスや取得URLは含めない。取り込み中の未確定項目は除外し件数を示す。書き出し先が管理領域内でないこと、空き容量、FAT32等のファイルサイズ制限を開始前に検査する。

エクスポートのスナップショットが参照する原本を固定し、終了までゴミ箱を空にする処理は待機する。「ゴミ箱を空にする」はアプリ内のUndo対象外と明示して確認し、OSのゴミ箱へ確実に移せた原本だけ台帳から除外する。完全削除へ切り替わる場合は実行せず失敗を示す。大容量・ごみ箱無効・移動途中の終了を検証する。OSから戻されて台帳のない原本はAL-04の未登録原本として再取り込みを案内する。Ctrl/Cmd+ZはAL-23のアプリ内の直前操作を戻す。

DB形式の更新前にDBのみの整合したスナップショットを作り、直近3世代を保持する。加えて1日1回、7世代のDBスナップショットを保持する。原本の完全バックアップとは区別する。起動時にDBの整合性と対応版を検査し、失敗時・未知の新しい版では書き込まず復旧を案内する。旧版へ戻した場合も新しいDBを黙って変換しない。復旧では採用するスナップショットの日時と失われる可能性のある最新変更を示し、破損したDBを保持する。

## 7a. クリップボード・ブラウザと原本の由来

| ID | 必須動作 | 受入条件 |
| --- | --- | --- |
| AL-28 | クリップボード画像はPNGに生成して保存し、ファイルのコピーは通常取り込みにする | 「素材」と履歴の画像項目に明示的な保存操作。画像名は「クリップボード画像 日時」、生成PNGのハッシュで重複判定。同じ画素でも異なるPNGバイト列なら別内容として扱う |
| AL-29 | ブラウザがOSへ渡した画像の内容/一時ファイルは取り込めるが、URLだけを渡された場合に自動取得しない | 画像内容は生成PNG、ファイルは通常取り込み。URLだけなら「画像をダウンロードしてから追加」を案内。受け取ったHTMLを実行しない |

Windowsではインターネット由来の印、macOSでは隔離属性を外部コピーへ付け直し、付与できない場合は該当コピーを安全に渡せない理由を示す。バックアップではmanifestの由来フラグを保持するため、FAT32等でOS属性を付けられなくてもバックアップ自体は失敗にしない。復元時にOSの印を付ける。ブラウザから受け取った内容はインターネット由来として扱う。実行ファイル・スクリプトを「OSで開く」際は起動を明示確認し、保存・プレビューの操作から自動実行しない。通常のデータファイルには追加の起動確認を一律に課さない。

## 8. データと処理の制約

- ローカルSQLiteを素材・分類情報の正本、通常ファイルを原本の正本とする。サムネイルとPDFページ画像は再生成可能。全件JSONの別正本を作らない。
- IDはUUID、内容ハッシュはSHA-256、日時はUTCのRFC 3339、サイズはバイト、再生時間はミリ秒、画像寸法はピクセル。未抽出の情報は`null`、空の所属は空集合、順序を持たない所属はIDで識別する。
- 管理対象のパスは領域内の相対パス。表示名と物理パスを分離し、Windows予約名・Unicode・大文字小文字の差で上書きや領域外参照が起きないようにする。公開形式には版番号と名前付きフィールドを使う。
- コピー・ハッシュ・メタデータ抽出・画像デコード・PDF描画をUIスレッドで行わない。同時実行数とキューを制限し、選択中、可視範囲、その先の順に処理する。原本のコピーはストリーム処理し、ファイル全体をメモリへ載せない。
- 初期の画像キャッシュ予算は展開済み画像256MiB。可視範囲の画像も含めて予算を管理し、大きい画像は縮小表示する。動画のプレーヤーとOSのメモリは別計測。ディスクでは一覧用サムネイルを1件64KiB以内・1素材につき1枚として保持し、最大`素材数×64KiB`の容量を空き容量確認に含める。大きなプレビューとPDFページ画像だけを2GiBのLRU予算にする。原本には適用しない。空き容量不足でサムネイルを作れないときも原本保存の状態を維持する。
- 隠れた画面の先読み・定期描画は停止する。動画再生は一つまで。保存中の原本処理は、画面を閉じてもアプリが動作している間は継続する。アプリ終了時は未完了記録から次回へ引き継ぐ。
- ライブラリの同時書き込みは一つのホストで管理する。バックアップとmigration中は整合したスナップショットを取得する。稼働中のDBを同期フォルダで複数端末から直接使わない。
- 元の私的なファイル名・画像内容・絶対パスを通常診断ログへ記録しない。未対応ファイルの保存後に実行やネットワークアクセスを自動で開始しない。

Schema、migration、バックアップ形式、代表fixtureの最小契約は実装の最初の工程で同時に作成する。依頼にない汎用同期基盤や形式変換基盤を先に実装しない。

## 9. 性能の合格条件

P95は95%の計測が値以内になる指標。ここでは達成を検証する予算として定め、全端末での保証やEagleとの速度比較には使わない。失敗時は処理箇所と条件を記録し、要件を黙って緩めない。

共通fixtureは1万件（JPEG/PNG 7,000、MP4 1,000、PDF 1,000、その他1,000）、日本語・英語の名前とタグ、重複・同名別内容を別セットで用意する。画像は12MPを中心に48MPを含め、動画は1080pと4K、PDFは1/100/1,000ページを含める。実メディアは再配布可能な生成fixtureまたは利用許可のある素材で作成し、版とハッシュで固定する。10万件ではDB・サムネイルを含めて規模を拡大する。

通常の内蔵GPU・8GiBメモリ・SSD、Windowsは4コア相当、macOSはApple M1相当を最低基準プロファイルにする。平均的な市場構成という統計上の主張ではない。利用できる実機を実装段階で確認し、具体的な機種・OS・画面倍率・WebView等の版を測定前に固定する。端末購入は今回の要件に含めない。今回の高性能Windows PCだけで合格にしない。基準実機がなければ性能受入を未検証にし、実装着手自体は妨げない。

合否の開始点はアプリが進入/操作/検索実行を検知した時刻、終了点は指定した素材の最初の実描画フレームとする。物理入力からの遅延、検索の150ms遅延、アニメーション完了は別に併記する。P01/P03は展開途中でも対象画像が描画されれば終了し、クリックを受け付ける時刻とは区別する。P95は昇順の`ceil(0.95×件数)`番目を使い、最大値・件数・失敗件数を併記する。

| ID | 計測 | 合格条件 |
| --- | --- | --- |
| AL-P01 | ウォーム状態でアプリの進入検知→素材サムネイル1件以上の実描画 | 100回計測しP95 ≤100ms。1万/10万件・直接移動/通常ホバー・取り込み中を別計測。機能無効時と同条件の開閉完了時間の差はP95 ≤16.7ms |

| AL-36 | グローバルショートカットから画面収録を開始・停止する | 既定Ctrl+Alt+R。設定画面を開かず、Windows標準の画面/ウィンドウ選択を表示し、同じキーまたはボタンで停止。音声と保存先には設定画面で保存した値を使う。設定画面を閉じても収録を続け、トレイに収録中の表示を残す。選択取消と開始失敗では待機へ戻り、保存失敗では通知とファイルを残す。音声付き・映像のみ・上限寸法への縮小の各経路で、確定したMP4をデコードして上下左右が取得元と一致することを確認する |
| AL-37 | PCの再生音とマイクを収録する | 既定の再生・入力デバイスを使い、個別にオン/オフ。48kHzステレオへ変換・混合し、音声付きMP4へ保存する。無音でも映像と音声の時間を維持する |
| AL-38 | 選択したライブラリのフォルダへ自動登録する | 素材画面の選択フォルダを撮影設定へ引き継ぎ、変更可能にする。通常の原本保存・重複・分類・変更通知を利用し、PNG/MP4を登録した後に一時ファイルをOSごみ箱へ移す |
| AL-39 | ショートカット競合と保存失敗を扱う | キーを変更可能にし、他アプリとの競合を表示。確定済みの保存待ちファイルを保持して再試行できる。収録対象の終了/サイズ変更、空き容量不足では収録を終了。通常の終了・更新時は収録を確定してから進める |

Windows開発版はWGCとWindowsのMP4エンコーダー、同梱したMITのNAudio 3.1.0を利用する。FFmpeg、Eagle、アカウント、APIキーの追加導入を利用条件にしない。収録は縦横比を保持して最大1920×1080・30fps、音声はAAC。音声デバイスはモノラル/ステレオに対応し、それ以外の設定では案内して開始を中止する。画面サイズ変更時は、現在の収録を確定してから新しい収録を始める。強制終了/停電でMP4が未確定の場合は、自動取り込みの対象にしない。

[実装と検証記録](../../progress/2026-10/2026-10-03_hover-pocket-capture.md)。長時間の音声同期、実複数画面/DPI、権限拒否・デバイス切断・実ディスク満杯・強制終了、公開配布およびmacOSは個別の追加受入とする。

## 14. 一覧の操作バー（2026-10-04追加）

- 検索・取り込み・貼り付け・整理を維持し、カメラとビデオのアイコンを置く。カメラは範囲撮影、ビデオは画面収録の対象選択を直接起動し、収録中の再操作は停止と保存を行う。設定画面は起動しない。
- 現在選択しているフォルダが1件ならそこへ保存し、ルートまたは複数選択時は未分類へ保存する。既定の撮影設定を上書きしない。
- 形式は画像・動画・PDF・その他と、保存済みの拡張子で絞り込む。並び順は取り込み日・名前・ファイルサイズを選び、昇順／降順を切り替える。一覧・ページ取得・範囲選択で同じ条件と順序を使う。
- 一覧サイズはバーで調整する。選択を保持し、カードの高さ・列数・仮想スクロールの行送りを一緒に変更する。表示サイズは次回も引き継ぎ、キーボードの矢印操作でも調整できる。
- 狭いパネルでは操作バーを折り返し、プレビュー中はこれまでどおり隠す。共通の上部ヘッダーと編集中のヘッダー維持は変更しない。

保存検索の追加条件と旧版での扱いは [共通契約](../../shared/asset-library/README.md) を正本とする。

2026-10-04追加: 一覧で選択した素材はDeleteキーでライブラリのごみ箱へ移す。複数選択を含み、Ctrl+Zで復元できる。文字入力・名前編集・画像編集中は素材を削除せず、ごみ箱内でも恒久削除を行わない。長押しと処理中の連打は重複処理しない。


## 15. カード操作とフッター（2026-10-04追加）

- カードへのホバーまたはキーボードフォーカスで右上に星を表示する。クリックした素材だけのお気に入りを切り替え、既存の選択とプレビュー状態を保つ。登録済みの星は常時表示する。
- 下部の操作ボタン行は廃止し、カードの右クリックでプレビュー・分類・名前変更・コピー・保存先・ごみ箱/復元・元に戻すのメニューを開く。選択済みカードへの右クリックは複数選択を維持し、未選択カードへの右クリックはそのカードを対象にする。
- メニューは画面内に収め、外側クリック・Esc・操作選択で閉じる。Shift+F10/メニューキーでも開き、上下矢印で項目を選べる。名前変更は右クリックした素材1件を対象にする。
- 素材画面だけ共通ヘッダー下の余分な余白を取り除く。件数・選択数・処理結果は最下部のフッターへまとめ、一覧の高さを確保する。プレビュー中は件数表示を隠す。


## 16. 撮影画面内での対象選択・編集・保存（2026-10-04追加）

- 素材一覧のフォルダ取り込みボタンを取り除く。フォルダのドロップ等、既存の取り込み処理は保持する。
- 撮影開始時の画面を固定し、ポインターの下にある表示中のアプリウィンドウを枠で強調する。非表示・最小化・別の仮想デスクトップのウィンドウとデスクトップ/タスクバーのホストを対象から除外する。デスクトップ上ではそのモニター全体を選ぶ。アプリを実際に前面へ切り替えず、撮影対象を強調する。
- クリック/Enterで対象を確定し、ドラッグで任意範囲も指定できる。負の画面座標と表示倍率を画素へ変換し、範囲外を切り取らない。
- 選択後は同じ画面・位置でペン、文字、四角、楕円、矢印、移動、消しゴムを使用し、枠付近に色/太さ・Undo/Redo・×・✓のツールバーを表示する。ツールバーをモニター内に収め、枠・アイコンを出力画像へ含めない。
- ✓/Enter/画像のダブルクリックでライブラリへ保存する。文字入力中のダブルクリックやEnterは通常の文字編集として扱う。×/Escは保存せず閉じる。保存中の連打は一度の処理にまとめ、保存失敗では編集を維持して再試行できる。
- このフローはAL-41の別ウィンドウ編集/自動保存の切替に代わる。旧capture-settings.jsonは読み込み可能なままとし、旧OpenEditorAfterScreenshotの値にかかわらず撮影中の編集ツールを表示する。ライブラリからの画像編集は従来どおり同じパネル内で行う。

## 17. スクショ通知からのドラッグ（2026-10-04追加）

- スクリーンショットのライブラリ保存が成功し、編集画面を閉じた後、操作中モニターの右下に画像付き通知を表示する。キーボードのフォーカスを奪わない。
- 通知の画像または本文をドラッグするとPNGファイルを外部アプリへ渡せる。ライブラリ原本とは別のoutboxコピーを渡し、Copyのみを許可する。受け取り側の編集や移動で原本を変更しない。通知終了後も受け渡したコピーを消さない。
- 表示時間は撮影・収録の設定画面で0〜30秒に変更でき、既定は5秒、0秒は通知なしとする。capture-settings.jsonのScreenshotToastSecondsへ保存し、旧設定では5秒を使う。
- マウスを置いている間・ボタンを押している間・ドラッグ中は残り時間を停止し、外すと再開する。成功したドロップ、閉じるボタン、次の撮影/収録、アプリ終了では閉じる。
- 取消や保存失敗では成功通知を出さない。通知用のコピーや描画に失敗しても保存済み画像を失敗扱いにせず、保存完了と通知側の問題を区別して伝える。
- 形式・並び順の選択メニューは選択肢まで不透明な暗い背景と明るい文字で統一し、Windowsの白い標準ポップアップで文字が見えなくなる状態を避ける。
