## 修正した動作

1. **原本の欠損・変更を保存成功と扱わない。** 同じ内容の素材がDBにあっても、管理原本の存在・サイズ・時刻・SHA-256を確認してから重複保存を確定する。確認できない場合は分類や原本を変更せず、入力とコピー済みファイルを保持する。撮影では完成済みの保存待ちフォルダを残し、復旧後の再試行を案内する。
2. **絞り込みに合わない複数選択を解除する。** 一覧にない選択IDすべてを現在の検索条件と照合する。単に別ページにある適合項目は選択を維持する。照合中は一括操作を受け付けず、確認に失敗した非表示項目も操作対象から外す。
3. **選択したフォルダを撮影へ渡す。** 単一のフォルダ選択を共通の処理で取得する。ルートや複数フォルダ選択では分類なしとし、任意の一つを勝手に選ばない。子フォルダ追加も同じ選択を使う。
4. **保存待ちの失敗を項目ごとに扱う。** 壊れたJSON、必須配列の欠落/null、欠損原本、ゴミ箱との重複があっても、後続の正常な撮影は取り込む。保存数と保留数、最初の理由を表示し、失敗した画像・動画は残す。

データ形式、SQLite schema、共通バックアップ契約の変更はない。保存済みの原本を自動で置換する機能は追加していない。
