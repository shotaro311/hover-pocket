# Windowsプレビューの描画乱れと収録の上下反転

2026-10-03、開発版`0.2.9-local.12`で修正。ユーザー提供の16.87秒のMP4を調べ、約7秒付近のプレビュー拡大時に黒い領域と内容のずれを確認した。動画は1920×810・30fpsのH.264とAAC音声で、上下反転は回転メタデータではなく保存画素に含まれていた。提供ファイルは変更していない。

## 原因と修正

### プレビュー

local.11はWebViewの再レイアウトを減らしたが、動くWebViewへの拡縮とネイティブウィンドウの連続リサイズが残っていた。今回の実機録画でも、その方式では黒い領域と描画位置の不一致が残った。

- 画像のデコード完了後に表示先の寸法を通知する。
- 拡縮中は開始位置と到着位置を含む固定のネイティブウィンドウを使い、移動する輪郭と内容の表示位置を合わせる。
- 到着先のWebView描画を待って画像を取得し、その画像をアニメーションする。終了時に実際のWebView表示へ戻す。WebView自体に連続した拡縮をかけない。
- 閉じる操作や次のサイズ要求が来た場合は古い処理を失効させる。取得失敗時は到着先へ切り替え、画像や操作を遮る状態を残さない。

主な変更は`PanelWindow.cs`、`AssetPaneController.cs`、`assets.js`。待機は上限を設け、失敗の診断記録を残す。

### 画面収録

取得したBGRA画素は上から下へ並ぶ一方、動画入力の行方向を明示していなかった。`ScreenRecorder.cs`で`MF_MT_DEFAULT_STRIDE`を正の`width × 4`へ設定し、取得画素とエンコーダーの解釈を一致させた。音声あり・なし・縮小の全経路に適用される。

正のstrideが上から下への並びを表すことは[MicrosoftのImage Stride仕様](https://learn.microsoft.com/en-us/windows/win32/medfound/image-stride)と[MF_MT_DEFAULT_STRIDE仕様](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-mt-default-stride-attribute)で確認した。既存MP4を変換する処理は追加していない。

100回反復は毎回の修正で自動的に行うものではない。変更した挙動と影響範囲に応じて検査を選び、AL-P08など反復測定を定めた性能受入とは分ける。今回はAL-P08全体の性能合格を主張しない。

途中の失敗ログも保存した。画素fixtureのfreeze不足、既存の出力ファイル、色変換の許容値、ライブラリ準備待ち、アニメーション終了前の検査には検査側の修正が必要だった。これらと、修正前MP4で再現した実際の上下反転を区別する。最終成功結果は以下の証拠に対応する。
