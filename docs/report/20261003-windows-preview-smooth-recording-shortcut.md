# Windowsプレビューのちらつきと録画ショートカット

2026-10-03、開発版`0.2.9-local.13`。ユーザー提供の`画面収録 2026-10-03 13-03-00.mp4`を確認し、local.12でも残った拡大途中の横ずれと細かい文字のちらつきを修正した。録画ショートカットは、設定画面を表示せず保存済みの設定で開始・停止する。

## 確認した問題と変更

提供動画は13.07秒、1920×810・30fps。映像の上下は正常だったが、4.3〜4.8秒付近で内容の大きさ・位置が途中で切り替わり、細かい文字がざわついて見えた。元ファイルは変更していない。

local.12は描画画像を使っていたが、画面内容の切り替え後に画像を取得し、その画像を外枠と一緒に拡縮していた。また、ネイティブウィンドウを移す瞬間に古い内容がずれるフレームが残った。今回の修正は次のとおり。

- ブラウザ内の内容を変える前に、現在の表示を取得して前面に保持する。
- 表示を保つ専用ウィンドウの位置を固定し、その裏でWebViewを到着先の寸法へ変更する。
- 到着先の描画を待って内容を切り替える。文字と画像の大きさ・位置は固定し、外枠と表示範囲をアニメーションする。
- 閉じる操作や次の要求で古い処理を失効させる。取得失敗・待機上限・閉じる操作では前面表示を解除し、操作できる状態へ戻す。

主な変更は`PanelWindow.cs`、`AssetPaneController.cs`、`assets.js`。任意のブラウザ描画を連続拡縮する方式から、固定した内容を外枠で見せる方式へ変えたため、画像全体を連続的にズームする動きではない。

## 録画ショートカット

`Ctrl+Alt+R`とトレイの収録操作から、設定ウィンドウを作成・表示する処理を外した。Windowsの対象選択に必要な小さな所有ウィンドウだけを一時的に使い、選択・取消・失敗後に閉じる。設定はトレイの「撮影・収録の設定…」で保存した音声・保存先を使う。

収録時間と容量監視は設定ウィンドウから独立させた。設定画面を閉じても収録は続き、トレイのメニューとツールチップで収録中を示す。開始・保存失敗はトレイ通知に出し、保存待ちファイルの既存の復旧経路を保つ。

## 通常起動とreadback

13:37 JST、収録・取り込み・purgeの未完了操作がなく、本体プロセスも存在しないことを確認した。設定ファイルと整合したSQLiteをバックアップしてから、local.13を通常起動した。依頼されたローカル修正の反映として、追加確認なしで実施した。

PID83468、期待する実行パス、応答あり、診断の`process.start`と`shell.ready`を確認。設定と撮影設定のハッシュは不変。素材3件・未完了取り込み0件・未完了purge0件・schema 1・quick_check=okが起動前後で一致した。証拠は`startup-readback.json`と`startup-backup-*`。

以前起動したlocal.12のPID98488は、この確認時点では存在しなかった。診断には開始と準備完了だけが残り、13:05以降のApplicationイベントにも該当するクラッシュ記録は見つからなかった。終了理由はこの記録から特定できない。

長時間収録、実機の複数モニター・GPU・DPIの全組合せ、macOSと公開配布は今回の検証範囲外。元のdirty checkoutは保持し、公開・pushは行っていない。自動起動登録は既存インストール版local.2のまま。
