# 付箋リマインダーの設計（2026-09-11合意済み）

ユーザー依頼: 作成時の日時指定、タイマー同様のHoverPocket画面通知と音、Codex音声対話によるリマインダー付き付箋作成、本番公開とこのMacの更新。

## 体験

- 新規・既存付箋の編集欄に任意のリマインダー日時を追加。初期は未設定。一度だけ通知する。
- 指定時刻に付箋をHoverPocketで表示し、タイマー同様の音と視覚通知を出す。停止操作を共通パネルに用意し、付箋を非表示にしていても操作できる。
- 変更・解除を可能にし、削除・アーカイブした付箋は通知対象から外す。
- スリープやアプリ終了中には鳴らせない。復帰・次回起動時に期限を過ぎた未確認分を通知する。同時期限は順に扱い、タイマー通知を失わない。
- 例: 「明日15時に資料を送る、とリマインダー付きの付箋を作って」。Codexは日時を明示し、保存後の読み戻しを根拠に完了を返す。

## 保存と操作契約

- 正本は既存StickyNotes/notes.json。従来の付箋へ任意のreminderを追加する。既存データは未設定として読み込む。
- 代表例: 変更前はtitle/body等のみ。変更後は同じ付箋にreminder={scheduledAt:日時,timeZone:"Asia/Tokyo",acknowledgedAt:null}を追加する。内部Dateの既存エンコードを尊重し、外部操作の日時はUTC offset付きISO 8601とする。nullは未確認、reminderの省略は未設定。
- 通知の確認状態を永続化し、再起動で確認済みの通知を繰り返さない。保存失敗時には設定完了や通知確認完了を返さない。
- 既存sticky.note.upsert/get v1は維持する。日時対応のv2をmacOSで追加し、音声経路を接続する。従来の操作は設定済みリマインダーを保持する。
- Windowsは既存v1のままとし、未実装の日時対応を利用可能と宣言しない。共有schemaと代表fixtureで互換性を検証する。
- 旧版は追加項目を読めても再保存で失うため、変更前データのバックアップを確保する。旧版への復旧はそのバックアップを用い、旧版で新しいリマインダーが機能するとは扱わない。
