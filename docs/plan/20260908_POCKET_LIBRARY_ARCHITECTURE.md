# ADR: 管理された機能ライブラリによるツール生成

Status: Accepted — ユーザーの2026-09-08「その内容で実装を進めてください」に基づく。

## 背景と判断

生成する個人用ツールに合わせて、Codexが登録済みライブラリを選ぶ。開発側が信頼済みの実装をアプリへ同梱し、利用者は自作ツール設定で有効・無効と利用関係を確認する。インターネットから任意の実行コードを取得する仕組みは今回の範囲に含めない。

既存のCapabilityRegistryは操作の権限・入力・出力・実行ハンドラーの正本として維持する。PocketLibraryCatalogは操作をライブラリへ所属させ、画面形式・記録保存・対応OS・依存関係を管理する。生成可能な操作と、既存ツール互換のため実行できる操作は区別する。これにより端末操作などを新規生成へ意図せず公開しない。

## 変更前と変更後

- 変更前: 生成可能な5操作が生成契約とプロンプトに固定記載され、HTML・collection・Codex接続の所属や利用関係がなかった。
- 変更後: 10個の同梱ライブラリを登録。生成時点の有効な台帳をプロンプトへ渡し、要求digestにも結び付ける。Hostは既存manifestから利用関係を導出し、生成候補・導入・復元・起動時の利用可否を再検査する。
- 例: 記録一覧は `pocket.collections`、HTMLの作業開始ツールは `pocket.html` + `pocket.timer` + `pocket.sticky` を使う。タイマーを無効にすると生成台帳からタイマー操作が消える。導入済み定義・無効化済みツール・アンインストール後に保持した定義・復元履歴のいずれかが使っていれば無効化を拒否する。

## 正本と互換性

- ライブラリのID・契約version・対応OS・依存関係・公開範囲: `PocketLibraryCatalog.bundled`。
- 個別操作のversion・permission・effect・入力/出力検査: 既存 `PocketCapabilityDescriptors`。同じ権限の別台帳を保存しない。
- ツールの依存関係: 既存manifestの `requestedCapabilities` / `surfaceKinds` / collectionsから都度導出する。新たな `libraries` 属性や別の依存関係DBは作らない。
- 永続化する追加設定はUserDefaultsの `disabledPocketLibraries: [String]` だけ。未保存は空配列と同義。既存manifest v1/v2、記録、履歴、バックアップの形式・digestは変更しない。
- ライブラリのversionは実装のビルド番号ではなく提供契約の版。既存の操作ID@version、surface/collection schema versionを変更する場合は別途互換性・移行設計が必要。別バイナリの自動更新やプラグイン市場は追加しない。
- Windowsは今回のmacOSツール実行を提供していないため台帳でmacOSのみを表示する。Windowsで検証済みとはしない。

## 追加・削除・更新

新しい機能は既存のHost操作ハンドラーと入力/出力契約を実装し、同梱リストにDescriptorを1個登録する。生成へ公開する操作を `generationKeys` で明示する。画面・コレクション機能も同じDescriptorで関連付ける。二重登録、存在しない依存先、循環依存は拒否する。

利用者の無効化は台帳から生成・実行対象を外す操作で、実行コードの削除や記録の削除ではない。直前に定義・履歴を読み直し、読めない場合は無効化しない。有効化は利用関係に問題があっても回復のため実行できる。生成中・導入確認中・バックアップ復元確認中は変更を停止する。

同梱実装を開発側が削除した場合も、依存する既存ツールは起動検査で拒否され、定義と記録は維持される。使われている契約の削除・非互換更新は受入時に既存ツールとの互換性確認が必要。

## Codexライブラリ

`PocketCodexLibrary`を本体専用モジュールとして登録し、音声Host/driverとツール生成factoryの入口を集約する。音声の既存coordinatorと生成のephemeral threadはそれぞれが所有し、キャンセルと終了を混同しない。本体が利用するため設定から無効化できない。

現行のツール生成もすでにApp Serverを使用していた。CLI execで生成しているという直前の説明は訂正済み。旧CLI adapterは既存検証用として変更しない。

2026-09-08の追加依頼により、生成したHTMLツールから文章処理を呼べる `pocket.ai-text` を追加した。Host専用の接続管理は引き続き `pocket.codex` が担当する。詳細は[文章処理契約](20260908_POCKET_AI_TEXT.md)を参照。

## 移行とロールバック

既存設定にキーがない場合は従来どおり全機能を利用できる。無効化設定を空配列へ戻せば従来の公開機能へ戻る。旧アプリへ戻した場合はこの追加キーを無視し、以前の全機能を利用できる。ライブラリ設定はツールバックアップに含めず、復元先Hostの設定を優先する。保存データの移行や削除は行わない。

## 選択肢と理由

任意バイナリを取り込む汎用プラグイン機構に比べ、同梱モジュールと既存の操作境界を使う方が現在の目的に必要な構成で、署名・権限・既存ツールとの互換性を維持できる。機能の追加配布にはアプリ更新が必要になる。

## 受入

台帳の循環・二重登録・OS差、Codex向け公開範囲、無効化による生成拒否、利用中/履歴の保護、再起動設定readback、既存記録の不変、旧manifest/digestの互換性を検証する。実モデルによる選択と小型画面の既存受入も確認する。公開・本番アプリ置換は別の依頼として扱う。
