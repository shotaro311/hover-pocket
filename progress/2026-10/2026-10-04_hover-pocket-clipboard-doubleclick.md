# クリップボードの読み込みとライブラリのダブルクリック

## 依頼と範囲

クリップボードを開く際のラグを改善し、ライブラリのファイル名をダブルクリックで変更できるようにする。ユーザー回答に従い、ファイル名は名前変更、サムネイルはプレビューとする。追加報告の「ダブルクリックでプレビューが開かない」も実マウス入力で再現・修正した。

既存のDownloads作業ツリーと `codex/windows-library-interactions` を使用。元の `code/shared/hover-pocket` と、前回のライブラリ修正の未コミット差分を保持した。今回の依頼に基づくローカル修正・検証・起動を実施。公開・push・自動起動変更は行っていない。

## 原因と変更

- `ClipboardHistoryStore.BuildState` が一覧更新のたびに全PNG原本を同期読み込みし、Base64で応答に含めていた。実履歴は画像20枚・約20.2MB。内容や画像は出力せず、ファイル数とサイズだけを調べた。
- 一覧応答はメタデータだけにし、新しい内部bridge `clipboard.getImage` で指定IDの画像を取得する。同時処理は2件、一覧は最大辺320pxのサムネイル、プレビューは原本PNG。ディスク読み込み・画像生成を画面スレッドの外で行い、見える範囲だけを取得、重複要求をまとめる。画像キャッシュは削除済みIDを除き、原寸は1枚まで保持する。保存形式は変更していない。
- 設定の再適用で監視が既に動いている場合は、現在のクリップボードを再取得しない。初回開始とプライベートモード解除の取得は保持する。
- ライブラリのカードを作り直さずに再利用し、選択バーの高さ変更や再描画でもダブルクリック対象を保持する。名前欄は選んだ1件だけの編集を開き、拡張子を除いて選択。Enterで保存、Escで取消。画像部分は従来のプレビューを開く。
- それだけでは実入力の不具合は残った。変更前・カード再利用後の両方で、信頼されたマウスクリックの `detail` が1→3になり、`dblclick` が届かなかった。WebView2CompositionControlの重複転送に対応する `PanelWebView` を追加し、通常のMouseDown転送は保持してOnMouseDoubleClickでの再送を止めた。同じ問題と対処は [WebView2公式リポジトリのIssue #5099](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5099) に報告されている。SDK更新はしていない。

## 測定と検証

生成した同一の1024×640 PNGを6枚（合計13,734,172 bytes）使用した限定計測。原寸表示は1024×640を維持する。

| 項目 | 修正前 | 最終候補 |
| --- | ---: | ---: |
| 一覧応答のJSON | 19,942,652 bytes | 3,254 bytes |
| 応答作成・JSON変換（初回） | 82.2ms | 3.1ms |
| 同上（続く2回） | 72.2 / 72.6ms | 0.034 / 0.017ms |
| 実WebViewの一覧表示 | 438.2ms | 64.2ms |
| 最初の画像の表示 | 438.3ms | 99.9ms |

前後各1回の画面表示計測であり、一般的な性能保証ではない。原寸全件の読み込みと転送がなくなったことは別の保存コア検査でも確認した。

- `--verify clipboard`: CRUD、上限、お気に入り、互換読み込み、PNG正規化・重複除外・復元・破損JSON・プライベートモードが通過。原本を排他ロックしたまま一覧応答が作れること、小さい画像の寸法と縦横比、原寸取得のバイト一致、削除済み/未知IDを返さないことも確認。
- `HOVERPOCKET_CLIPBOARD_LOAD_VERIFY_ONLY=1`: 一覧・タブ・お気に入り・プレビュー・削除UI・再描画抑止の既存検査と原寸表示が通過。
- `HOVERPOCKET_PREVIEW_MOTION_VERIFY_ONLY=1`: 実マウスのサムネイルダブルクリックでプレビュー、ファイル名ダブルクリックで名前編集と取消が通過。計3回の開閉、Space操作、デコード済みサムネイル維持、30/120/300msの途中取消が通過。100回開閉は未実施。
- `HOVERPOCKET_ASSET_VERIFY_ONLY=1`: 選択・名前編集を含むUI24項目、H.264再生と全画面、編集保存と原本保持、パネル/整理画面のネイティブドラッグとUndo、ホバー離脱・フォーカス離脱、描画待ちの復旧、PDF等の既存検査が通過。初回は名前ツールチップへ操作説明を入れたため検索fixtureが失敗。元の完全なファイル名を保持するよう戻し、最終候補で全体を再検査して通過した。
- Debug / Release build: 警告0、エラー0。JS17ファイルの構文検査と `git diff --check` が通過。
- self-contained候補を作り、インストール版のOAuthメタデータを保持したことを値を表示せず検証。`--verify release-config` 通過。

根拠は `artifacts/clipboard-load-20261004/` の `before.log`、`clipboard-final.log`、`clipboard-core.log`、`double-click-before.log`、`double-click-after.log`、`double-click-host-fixed.log`、`asset-ui.log`、`asset-ui-final.log`、`release-config.log`。失敗ログも保持した。
