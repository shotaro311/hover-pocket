# 2026-11-19 AI Usageの表示の作り替え（一覧とメーター、Windows・macOS、未配信）

## 目的

ユーザーが本番0.2.20のAI Usageを見て「レイアウトが見にくい。テキストも多いし、ぱっと見ごちゃっとして見える。並び替えも可能にしたい」と指摘した。カードごとの「HH:mm 更新」、2行に折り返すリセットの文、プラン名、使用率と残高の混在が原因だった。

## 決めたこと（ユーザーとモックアップで合意）

- 3案（一覧表、注意順のサマリー、リングのタイル）を示し、ユーザーは「一覧」と「メーター」を切り替えられる形を選んだ。
- 一覧: 列の見出しを押すたびに昇順・降順。別枠は名前とリセットまでの時間を両立。Antigravityのモデル名は出さない。
- メーター: 高級車のデジタルタコメーター風。区切りの数字は出さない。枠が複数あるサービスはメーターを横に並べる。
- 色は「70以上は青、50以上は緑、25以上は黄、それ未満は赤」。使用率に当てはめると危ない枠ほど青になるため、残りの割合に当てはめ、数字も残りにした（ユーザーが一覧も残りにそろえることを選んだ）。色の凡例は出さない。
- 対象はWindows版とmacOS版の両方（ユーザーの選択）。
- 正本は[設計書](../../docs/design/2026-11-19_ai-usage-list-and-meter.md)。要件は[要件](../../docs/requirement/requirements.md)の2026-11-19の節。

## 進め方

- 設計とレビューはClaude、実装はCodex（共通ルールの振り分け）。Windows版はこのPCのCodex（gpt-6.2-sol / high、作業フォルダ内の書き込みのみ）、macOS版はMacのCodex（codex_peer経由、ブランチ `codex/mac-ai-usage-layout-20261119`）。依頼文と報告は `handoff/2026-11-19-ai-usage-layout/`（Git管理外）。
- Codexのサンドボックスでは描画の検査が動かないため、Windowsの `--verify ai-usage` はClaudeがサンドボックスの外で流した。

## 作ったもの

- 見出し: タイトル、`一覧` / `メーター` の切り替え、更新時刻は1回だけ、更新ボタン。
- 一覧: 行がサービス、列が5時間・1週間・別枠。セルは残りの数字（4色）とリセットまでの短い時間（`4:49`、`3日21時間`。正確な日時はヒント）と棒。列の見出しで少ない順・多い順、値のないサービスは常に末尾、「自分の順に戻す」。見出しの行はスクロールしても残る。残高だけのサービス（Claude API、Colab）は表の下の札。
- メーター: 270度の弧、5%ごとの目盛り、4色の細い帯、区切りの点の値の弧、白い針、中央に「残り」と数字。枠の名前が長いときは省略し、同じ名前の枠の長さは2行目に付ける。残高は走行距離計のような数字の箱。
- 並び順: 取っ手のドラッグと、設定のAI欄の上下ボタン。表示の種類、順番、並び替えの状態を保存する。
- 古い値・エラー・未サインイン: 判定は変えず、数字と棒・弧だけを薄くし、名前の下に黄色の「HH:mm の値」、理由は数字の欄の下に2行まで。未サインインは「設定を開く」のボタン。

## 検証

- Windows: Release・Debug（警告をエラー）のビルドで警告0。`--verify ai-usage` 207項目合格（作り替え前は187）。追加分は、切り替えの保存、残りと4色、列の並び替え、上下ボタンと保存、残高だけのサービスの扱い、数字と時間が重ならないこと、理由の位置と折り返し、メーターの寸法と名前の収まり、見出しの固定、古い値の薄め方など。最終のコードで、CIと同じ手順（ビルド2種、契約チェック、検証14種類）がすべて合格。途中で `--verify ui` の素材ライブラリの操作の検査が2回失敗したが、作り替え前の本番0.2.20でも同じく失敗し（パネルにクリックが届かない）、画面の状態を戻した後の最終の実行では合格したため、このPCの画面の状態によるものと判断した。失敗した実行が残した一時ファイル（`%TEMP%\assets-*.png`）はごみ箱へ移した。
- macOS: `swift build -c debug -Xswiftc -warnings-as-errors` 警告0、`--verify-ai-usage` 188項目、`--verify-panel-layout`、`--verify-chat` 48項目が合格（MacのCodexの報告。画像5枚はClaudeが確認）。
- 未確認: 実際のマウスでのドラッグとヒント、VoiceOver・ナレーターの読み上げ、実アカウントでの表示。

## レビュー

- 実装（Codex）はClaudeがレビューした。Windowsはコードと描画の画像、macOSは設定の読み込みのコードと画像。指摘（残高だけの行、数字と時間の重なり、理由の切れ、メーターの大きさと名前のはみ出し、スクロールバー、設定の上下ボタンの位置、macOSの2分で薄くなる独自の決まり、取得できない枠の文字のはみ出し）は、Codexが直した。
- デザイン（Claude）は、Codex（gpt-6.2-astra / high、読み取り専用、新しい会話）が両OSの実画面で2回レビューした。1回目: 要修正3件（長い枠名が目盛りに重なる、一覧の見出しがスクロールで消える、macOSの「設定を開く」が文章に見える）、設計との違い2件、提案3件。重大1件は検証用の架空データ（状態ごとの残高を3つ並べている）によるもので、対応しなかった。2回目: すべて解消、新しい重大・要修正なし。

## 残り

- 配信（Windows・macOS）はユーザーの判断待ち。macOSの変更はMacの作業ツリーに未コミット。

## 0.2.21のあとの改訂（セクション分け、数字の書体、並び替えの不具合）

- 本番の0.2.21を見たユーザーの指摘: 「APIクレジットとサブスク枠の表示をセクション分けしてほしい」「並び替えの時に画面が真っ暗になり並び替えできない」「数字のフォントが見にくい（カンマやピリオドが大きいか幅広）」。イメージを2回見せ、書体は「もう少しモダンなアップルっぽいやつで」を受けてInterに決めた。
- 並び替えの原因: 取っ手が標準のドラッグで、行やまとまり全体をドラッグ中の画像にしていたため、HoverPocketの暗い透明な窓で大きな黒い四角として出て、落とす先も働かなかった。検査は合成した `DragEvent` を送るだけで、この不具合を見逃していた。ポインタ操作（押す・動かす・離す）に替え、矢印キーでも動かせるようにした。Windowsは実際のマウス入力でつかんで動かす検査を足した（`HOVERPOCKET_AI_USAGE_NATIVE_MOUSE=1` のときに流れる。OSのドラッグが始まらないことも確かめる）。macOSはつかんでいる間だけパネルを閉じない。
- セクション: 「サブスクの利用枠」と「クレジット・残高」。Codexのクレジットは残高のカードへ移し、順番はセクションごとに別々に保存する。
- 書体: WindowsはInter 4.1（作者の公式リリース `rsms/inter` v4.1 の `Inter-4.1.zip` から `web/InterVariable.woff2` と許諾書だけを取り出して同梱。SIL Open Font License 1.1）、macOSはSF Pro。どちらも数字の幅をそろえる。
- 進め方は前回と同じ（設計はClaude、実装はCodex。Windowsはこの PC、macOSはMac）。デザインレビュー（Codex、Astra / high）の1回目: 重大なし、要修正1件（Windowsの一覧で長い別枠の行の数字が中央に寄る）、提案（Windowsの表示の切り替えの選択中が分かりにくい）。どちらもClaudeがCSSで直した（行を上にそろえる、選ばれていない側を塗らない）。切り替えの件は、色の切り替え（0.12秒）の途中を撮っていたのが主な原因で、撮る前に待つようにし、検査を足した。
- 検証: Windowsの `--verify ai-usage` 226項目（実際のマウスでの並び替えを含む）、macOSの `--verify-ai-usage` 205項目、`--verify-panel-layout`、`--verify-chat`、CIと同じ `swift build -Xswiftc -warnings-as-errors` が合格。macOSは、CIで見つかった型推論の時間切れ（検証コードの大きなクロージャ）も直した。
